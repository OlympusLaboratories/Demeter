### Platform Infra — DA COP submission incident (PLAT-1974), on-call
- Grafana fired "DA COP submission missing (gridops ERCOT)". Dylan root-caused it: the `gridops-cop-submission-temporal-worker-prod` worker had been crash-looping (OOM) since an auto-deploy the prior night; capped at 0.5G, the build pushed startup over the limit, so no healthy worker existed when the 2:08pm CT submission fired. Identified that today's run was still queued in Temporal and would self-submit once the worker was healthy. Fix MR bumped memory 0.5G→2G on both prod and dev worker deployments. Travis praised the find ("good find", "we definitely need a claude on call bot"). Victor noted parallel memory issues elsewhere (cuopt dependency). Follow-up: Travis asked Dylan to open a ticket to add CrashLoopBackOff alerts on owned deployments; Dylan agreed.

### Platform Infra / Retail — ArgoCD stuck-sync debugging (with Vrinda, Madeline, Travis)
- Madeline reported a cronjob (`ercot_retail/staging`) that didn't pick up her merged v3→v5 change while sibling v13 jobs deployed fine. Vrinda investigated; the root cause was the `bid-ercot-retail` ArgoCD app stuck in a failed sync-retry loop since ~Jul 6, endlessly re-applying a stale pre-merge revision (GKE Autopilot's admission webhook kept mutating pod resources, so the diff never converged; `retry.limit = -1` retried forever). Vrinda asked Travis/Dylan about the infinite retry setting. **Dylan explained the design intent**: the infinite retry is intentional so a single MR can carry both kube-manifest and terraform changes — the app stays unhealthy/retrying until the manifest merges to main, then auto-heals, avoiding a two-MR dance. Vrinda proposed adding an alert instead of changing the retry limit (MRs tlaloc-env !2525, !2526). Travis floated moving templates to Helm charts long-term.

### Build/CI — kubeconform GitHub rate-limit incident (on-call)
- Multiple engineers (irene, Eric Luxenberg, Madeline) hit failing MR pipelines. **Dylan diagnosed** the lint job (kubeconform, validating kube manifests) was failing because it downloads schemas from a GitHub CDN and was being rate-limited. He kept restarting jobs to unblock time-sensitive merges (ISONE DA cronjob fix), gave a workaround (comment out the lint job), and got both pipelines green. Followed up with Travis on a durable fix — mirroring/caching the schemas to kill the external dependency (Travis had set up a GitHub API key; Dylan noted Claude suggested caching and offered to pair on it).
