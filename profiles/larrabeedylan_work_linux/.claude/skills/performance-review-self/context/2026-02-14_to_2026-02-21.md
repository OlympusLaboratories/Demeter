- **Channel:** platform-infra-team
- **People involved:** Dylan, Mark, Travis
- **What happened:** Dylan discovered that the Cloud Trace → BigQuery sink was silently dropping all spans. After hours of debugging, he filed a GCP support ticket (first time using GCP support). Google support confirmed that the sink only works with the legacy `cloudtrace.googleapis.com` API, not the OTLP/telemetry API used by GKE's managed OTEL collector. Dylan then deployed a custom OTEL collector using the `googlecloud` exporter as a workaround, getting Buildkite trace data flowing into BigQuery and Grafana.
- **Dylan's role:** Led the investigation, filed the support ticket, designed and implemented the workaround. Mark helped with GCP support access permissions.
- **Outcome:** Buildkite trace data now flows into BigQuery via custom OTEL collector. Mark later built on this with a new Grafana dashboard using BQ analytics.

### 3. False Positive CronJob Failure Alerts (#prod, #platform-infra)
- **Channel:** prod, platform-infra
- **People involved:** Dylan, Marshall, Mark
- **What happened:** Marshall flagged noisy CronJob Failure alerts. Dylan quickly identified the root cause: his earlier MR (!1987) that added kube-state-metrics label scraping to the build cluster caused Prometheus to pick up ephemeral Buildkite pod failures as "CronJob Failures" since they appeared under `namespace=production`. Dylan provided a detailed analysis with two fix options (quick filter vs proper monitoring config). He also identified that the kube-state-metrics `--metric-labels-allowlist=pods=[*]` was causing timeout issues and narrowed it to specific labels.
- **Dylan's role:** Rapid incident response, root cause analysis, immediate mitigation (narrowed label allowlist), provided fix options to Marshall.
- **Outcome:** Marshall applied the quick alert filter fix; Dylan has a draft MR (!1988, PLAT-1165) for the proper monitoring config fix.
